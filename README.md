# К столу

Личная книга рецептов. Статический сайт без сборки и внешних библиотек. GitHub Pages для сайта, Supabase для общей книги. Тексты взяты из сохранённых авторских описаний, фотографии — реальные кадры из видео. Исходные MP4 в сайт не входят.

## Открыть локально

Откройте `index.html` двойным щелчком или запустите `python -m http.server 8765 --bind 127.0.0.1` в этой папке и перейдите на http://127.0.0.1:8765. Для постоянного адреса на всех устройствах используйте GitHub Pages.

## Опубликовать через GitHub Desktop

1. File → Add local repository → выбрать **эту папку** `recipe-book`. Если репозитория ещё нет, выбрать **create a repository here**. Репозиторий должен находиться именно внутри `recipe-book`, а не в родительской папке с видео.
2. Создать коммит и выбрать Publish repository. Для GitHub Free нужен публичный репозиторий. В нём только сайт и фото; тексты рецептов станут публичными.
3. На GitHub: Settings → Pages → Source → **GitHub Actions**.
4. Во вкладке Actions дождаться задачи **Publish recipe book**. Если коммит был отправлен до включения Pages, открыть задачу и нажать Run workflow.
5. Постоянная ссылка появится в Settings → Pages и в выполненной задаче. Работает без своего домена и включённого компьютера.

## Что работает

- Поиск по названию, ингредиентам, тегам и авторскому тексту.
- Категории: завтрак, обед, ужин, выпечка, десерт, напитки. Один рецепт может быть в нескольких категориях.
- Фильтр по нескольким тегам (пересечение), избранное, таблица и сетка.
- Карточка с ингредиентами, шагами, исходным текстом и ссылкой на VK.
- Общий список покупок с разделением по блюдам и отметками купленного.
- Свои теги, категории, исправления ингредиентов и шагов, загрузка фото.
- Синхронизация правок, фото, тегов, избранного и покупок после входа; экспорт/импорт резервной копии.

## Вход и сохранение

Каталог, карточки и покупки открываются в интерфейсе после входа. Без входа любые маршруты показывают форму авторизации. Это экран доступа к интерфейсу: исходная коллекция и фото по-прежнему находятся в публичных файлах GitHub Pages; полной приватности файлов такая схема не обеспечивает.

После входа изменения общие для двух разрешённых участников и загружаются при открытии и примерно каждые 10 секунд. Правки отправляются сразу, если есть связь. При потере соединения сохраняется очередь на устройстве; после восстановления связи отправка повторяется. Одновременные изменения одной записи требуют выбора версии в настройках. Вид каталога остаётся личным.

Без входа изменения сохраняются только в браузере. При первом подключении прежние правки этого устройства добавляются автоматически, если для записи ещё нет общей версии. Существующие общие записи имеют приоритет. Импорт JSON заменяет общие данные после подтверждения. Не очищайте данные сайта, пока остаются неотправленные правки.

`cloud-config.js` содержит URL и публичный publishable key, рассчитанный на размещение в браузере. Доступ к данным ограничен RLS и серверным списком разрешённых email; сами адреса не хранятся в репозитории. Секретные и service-role ключи в клиент не добавлять. Схема в `supabase/schema.sql`. Проверка транспорта: `node tools/test_cloud.cjs`.

Исходная коллекция хранится в `recipes.js`; её обновления публикуются через GitHub. Пользовательские правки хранятся отдельно в общей базе.

У пяти рецептов нет исходного текста. У двух нет фотографий, поскольку публикация содержала только текст и фото, которые не были скачаны. В этих карточках можно добавить своё фото. У некоторых авторов отсутствуют шаги, количества или единицы — невыясненные значения не выдумывались. Кадр видео может содержать процесс приготовления или надписи автора, его можно заменить.

## Обновить коллекцию из локальных файлов

`python tools/build_library.py` из этой папки. Требуются оригинальные папки рецептов на уровень выше, Python, FFmpeg/ffprobe. После редакторской правки `recipes.js` не запускайте импорт заново без сохранения правок: он пересобирает базу. Для работы опубликованного сайта Python и FFmpeg не нужны.
